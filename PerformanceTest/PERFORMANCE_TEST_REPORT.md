# PaperMate 非功能性与性能测试报告

## 1. 结论

优化后的后端配置已满足“100 条以上数据、100 并发下检索、问答和学习管理响应时间小于 3 秒（不计 LLM 响应）”的性能验收要求。基准使用 4 个 Uvicorn worker、显式数据库连接池、短时鉴权缓存和同机确定性 LLM stub；三个场景均为 100% 成功，最大响应时间均低于 3 秒。

## 2. 测试环境与方法

- 日期：2026-07-28
- 后端：FastAPI/Uvicorn，Python 3.12.3，SQLite 临时数据库，4 个 Uvicorn worker。
- 数据：脚本自动写入 100 篇论文元数据；第 1 篇额外写入 2 个原文块和 1 条结构化摘要，使问答接口具备真实的检索证据。
- 并发：每个场景使用 100 个并发 HTTP 请求，先执行 5 次预热请求，再一次性发送 100 次测量请求。
- 判定：100 个请求均为 HTTP 2xx，且最大单请求响应时间严格小于 3,000 ms，才判定场景通过。
- 问答：使用同机 OpenAI-compatible HTTP stub 返回确定性 JSON；这保留了 Web 鉴权、证据检索、问答规划和响应组装路径，但不包含真实模型推理及外网传输时间。
- 隔离：每类接口均在新的 Uvicorn 进程中测试，共用同一临时数据库；不写入开发库 `data/dev.db`。
- 优化：每个 worker 配置 30 个常驻连接、20 个溢出连接和 3 秒连接池等待；已验证 token 在 60 秒内复用用户身份，账户禁用、删除或改密会主动清除对应缓存。

可重复执行：

```bash
cd SE26Project-04
TechPrototype/backend/.venv/bin/python PerformanceTest/scripts/performance_web_benchmark.py
```

原始机器可读结果写入被 Git 忽略的 `PerformanceTest/reports/performance-web.json`。

## 3. 100 并发结果

| 场景 | 成功/总数 | 错误数 | P50 | P95 | P99 | 最大值 | 平均值 | 吞吐量 | 结果 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 检索：`GET /api/papers` | 100/100 | 0 | 389.51 ms | 522.99 ms | 544.67 ms | 548.30 ms | 364.11 ms | 169.38 RPS | 通过 |
| 学习管理：`GET /api/learning/actions` | 100/100 | 0 | 124.23 ms | 200.87 ms | 222.07 ms | 222.50 ms | 132.33 ms | 388.81 RPS | 通过 |
| 问答：`POST /api/papers/1/qa`，本地 stub | 100/100 | 0 | 509.39 ms | 612.17 ms | 629.27 ms | 654.28 ms | 503.53 ms | 150.17 RPS | 通过 |

优化前的单 worker、默认 SQLite 连接池基线在 100 并发下仅有 1% 至 13% 请求成功，且大量请求在客户端 10 秒超时。优化后将请求分摊到 4 个 worker，扩大每 worker 的连接池并减少 SQLite 无意义的连接存活探测；学习管理和问答的重复 token 用户查询通过短时缓存消除。上述结果表明当前应用层已达到本次验收门槛。

本次临时数据库测试用于验证应用的并发模型。正式部署仍必须使用 PostgreSQL，以实际数据库机器、真实数据规模、网络拓扑和模型服务进行一次同口径复测；SQLite 不应作为生产性能结论的依据。

## 4. Web 客户端与兼容性

前端生产构建成功，产物包含浏览器可加载的 `index.html`、CSS 和 JavaScript。Vitest 在设置 `TMPDIR=/tmp` 后执行成功：`3 files passed, 39 tests passed`。

本机未安装 `agent-browser`，且受限环境不能进行真实浏览器自动化，因此本次**不能**以证据证明 375x667、768x1024、1440x900 等不同视口下的实际布局兼容性。构建与单元测试只能说明 Web 客户端可生成，不能替代响应式浏览器验收。后续应在这三个视口执行登录、检索、论文详情、问答、学习管理的截图和点击冒烟测试，并检查横向溢出、遮挡和触控操作。

## 5. 准确率验收状态

已执行后端确定性流程验证：`python -m harness e2e` 成功，确认解析任务完成、文本块/结构化摘要/图谱写入、问答返回内容且引用来自证据；相关测试集运行结果为 `23 passed`。这些测试验证功能契约和“回答必须有依据”的约束，**不等同于准确率**。

要验收“解析、检索和问答准确率均大于 90%”，需要补充独立的人工标注集，建议最少各 100 个样本：

- 解析：以人工校验的摘要、方法、实验、局限和页码/文本证据为标准，按字段计算正确率。
- 检索：每条查询标注相关论文集合，计算 Precision@10、Recall@10，二者或预先约定的 F1 均应不低于 90%。
- 问答：每题标注可接受答案与支持证据，要求答案正确且每个主要结论可由引用片段支持；拒答类问题也要计入，以防止无依据回答。

在上述标注集和固定评分规则加入前，准确率要求应保持“待验收”，不能据现有单元测试宣称已达 90%。

## 6. 已完成优化与后续工作

1. 已完成：数据库引擎支持每 worker 显式连接池参数；SQLite 不再对每次连接执行网络数据库才需要的存活探测。
2. 已完成：生产服务模板改为 4 个 Uvicorn worker；生产环境变量模板给出 PostgreSQL 及连接池上限，避免 worker 数量与数据库连接数失配。
3. 已完成：短时鉴权缓存减少受保护读接口的重复用户查询；账户禁用、删除、改密会主动失效该用户的缓存 token。
4. 后续必须执行：在 PostgreSQL 和真实数据规模下运行相同脚本，并增加检索、学习管理与问答混合负载及 30 分钟持续负载。
5. 后续建议执行：在请求指标中输出 `retrieval_ms`、`llm_ms`、`total_ms`，使“不计 LLM 响应时间”的验收具备可审计证据。
